### 4️⃣ **데이터베이스 및 캐시 준비**

#### Firebase 초기화 중...
- **위치**: `electron/main.js` 810줄
- **내용**:

  - Firebase Auth 준비
- **목적**: 백엔드 데이터베이스 연결 준비

#### IndexedDB 캐시 준비 중...
- **위치**: `electron/main.js` 814줄
- **내용**:
  - Firestore IndexedDB Persistence 활성화
  - 오프라인 데이터 저장소 준비
  - 캐시 크기 설정 (200MB)
- **목적**: 오프라인 지원 및 빠른 데이터 접근

#### 중요 데이터 프리로딩 중...
- **위치**: `electron/preload.js` 61-101줄 (`preloadCriticalData()`)
- **내용**:
  1. **인증 상태 확인**
     - `localStorage.getItem('auth-store')`에서 로그인 상태 확인
     - 사용자 UID 추출
  2. **네이티브 파일 캐시 로드**
     - 메인 프로세스에 저장된 캐시 데이터 읽기
     - 최대 500개 항목 메모리에 로드
  3. **IndexedDB 준비 확인**
     - IndexedDB가 준비될 때까지 대기
     - Firestore 캐시 접근 가능 여부 확인
- **목적**: 앱 시작 후 즉시 사용할 데이터를 미리 메모리에 로드

## 🎯 요약

### 실제로 로드되는 데이터
1. **네이티브 파일 시스템 캐시** (최대 500개 항목)
   - 이전에 저장된 Firestore 데이터 캐시
   - 파일 위치: `%AppData%/app-name/cache/data-cache.json`

2. **인증 상태** (localStorage)
   - 로그인 여부
   - 사용자 정보

3. **IndexedDB 캐시** (Firestore)
   - 최대 200MB 오프라인 데이터
   - Firestore가 자동으로 관리

### 실제로 초기화되는 시스템
1. **IPC 통신 시스템** - 메인/렌더러 프로세스 간 통신
2. **에러 처리 시스템** - 전역 에러 핸들러
3. **업데이트 시스템** - 자동 업데이트 체크
4. **Firebase SDK** - 데이터베이스 연결
5. **IndexedDB Persistence** - 오프라인 캐시

### 시간 소요
- **네이티브 캐시 로드**: ~10-50ms
- **시스템 초기화**: ~100-200ms
- **HTML 파일 로드**: ~50-200ms (프로덕션) / ~100-500ms (개발)
- **Firebase 초기화**: ~100-300ms
- **프리로딩**: ~200-500ms

**총 예상 시간**: ~500-1500ms (0.5-1.5초)

## 📝 참고

- 프리로딩은 **비동기**로 실행되며 앱 시작을 블로킹하지 않음
- 네이티브 캐시는 앱 시작 전에 로드되므로 스플래시 화면에 표시되지 않음
- IndexedDB는 Firestore SDK가 자동으로 관리하므로 별도 로드 불필요
- 모든 로딩은 **실패해도 앱은 정상 실행**됨 (선택적 최적화)
