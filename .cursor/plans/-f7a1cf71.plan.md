# 썸네일 생성 전략 결정 및 업로드 로직 품질 개선 계획

## 0. 피처별 업로드 경로 분석 및 최적 전략 결정

### 0.1 현재 업로드 경로 정리

**확인된 경로:**

- `quality-issues/${Date.now()}` (하위 경로 포함)
- `quality-inspections/${docId}` (하위 경로 포함)
- `sample-requests` (루트)
- `jig-images` (루트)
- `production-requests` (루트)
- `announcements` (루트)
- `users/{userId}/profile/` (하위 경로 포함, 추정)
- `chat/messages/${Date.now()}` 또는 `chat/messages/${chatRoomId}` (하위 경로 포함)
- `packaging-reports` (확인 필요, 이미지 업로드 사용 여부 확인)

**문제점:**

- 하위 경로가 다양함 (`/${Date.now()}`, `/${docId}`, `/${chatRoomId}` 등)
- 현재 `allowedFolders` 방식은 하위 경로 매칭은 되지만, 새로운 경로 추가 시 수동 업데이트 필요
- 경로 패턴이 일관되지 않음

### 0.2 두 가지 옵션 비교

**옵션 1: 피처별 경로에 대응 (현재 방식 개선)**

- 장점: 
- 필요한 이미지만 처리 (비용 절약)
- 제어 가능 (특정 폴더만 처리)
- 불필요한 이미지 처리 방지
- 단점: 
- 경로 관리 복잡 (하위 경로 다양)
- 누락 가능성 (새 피처 추가 시)
- 유지보수 부담 (경로 추가/변경 시 Functions 수정)
- 코드 복잡도 증가

**옵션 2: 모든 이미지 처리 (권장)**

- 장점: 
- 단순함 (경로 체크 불필요)
- 누락 없음 (자동 처리)
- 유지보수 용이 (새 피처 자동 지원)
- 확장성 (미래 경로 자동 지원)
- 코드 단순화 (버그 감소)
- 단점: 
- 불필요한 이미지도 처리 (비용 증가 가능)
- 하지만 썸네일 생성 비용이 낮음 (WebP, 300px, 빠른 처리)

### 0.3 최종 결정: 옵션 2 (모든 이미지 처리) - 권장

**이유:**

1. **비용 효율성**: 썸네일 생성 비용이 매우 낮음 (WebP, 300px, ~0.1초)
2. **유지보수성**: 새 피처 추가 시 자동 지원, 코드 변경 불필요
3. **안정성**: 경로 누락으로 인한 버그 방지
4. **단순성**: 코드 복잡도 감소, 버그 가능성 감소
5. **확장성**: 미래 경로 변경에도 자동 대응

**예외 처리:**

- 이미 썸네일 파일 (`_thumb.webp`)은 제외 (무한 루프 방지)
- 특정 폴더 제외 목록 (선택사항):
- `electron-releases/` (설치 파일)
- `mobile-releases/` (APK 파일)
- `public/` (공개 파일, 필요시)

## 1. 썸네일 생성 문제 해결

### 1.1 Firebase Functions 트리거 로직 단순화

**파일**: `functions/triggers/imageOptimization.js`

- `allowedFolders` 제거 또는 예외 폴더만 관리
- 모든 이미지 파일 처리 (이미지 타입 체크만)
- 제외 폴더 목록 추가 (선택사항, `electron-releases`, `mobile-releases` 등)
- 에러 로깅 강화 (상세한 에러 정보, 통계)

### 1.2 썸네일 URL 생성 로직 개선

**파일**: `src/shared/utils/imagePathMigration.ts`

- `getThumbnailURL` 함수의 URL 재구성 로직 개선
- 버킷 이름 추출 로직을 더 안정적으로 변경
- `convertStorageBucketURL`과 통합하여 일관된 URL 처리
- 다양한 URL 형식 지원 (기존 버킷, 새 버킷)

### 1.3 썸네일 존재 확인 로직 추가

**파일**: `src/shared/utils/imagePathMigration.ts`

- `checkThumbnailExists` 비동기 함수 추가
- Storage에서 실제로 썸네일 파일이 존재하는지 확인
- `LazyImage` 컴포넌트에서 썸네일 존재 여부 확인 후 로드
- 폴백 로직 개선 (썸네일 없으면 원본 로드)
